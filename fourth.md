Используя подтверждённые результаты технического анализа проекта и созданный AGENTS.md, подготовь документацию в docs/ai/.

Не изменяй исходный код приложения.

Создавай документы по одному в следующем порядке:

1. architecture.md
   - фактическая архитектура проекта;
   - структура модулей;
   - зависимости;
   - правила расположения нового кода;
   - конкретные примеры существующих файлов.

2. coding-standards.md

   - TypeScript;
   - компоненты и хуки;
   - соглашения по именованию;
   - типизация;
   - обработка ошибок;
   - подтверждённые антипаттерны.

3. components.md
   - UI-библиотеки;
   - переиспользуемые компоненты;
   - формы;
   - стилизация;
   - правила создания новых UI-компонентов.

4. api-and-state.md
   - API-клиенты;
   - управление состоянием;
   - запросы;
   - обработка ошибок;
   - кэширование, если используется;
   - реальные примеры потоков данных.

5. testing.md
   - тестовая инфраструктура;
   - существующие соглашения;
   - команды проверок;
   - рекомендации по тестированию разных типов изменений.

Для каждого документа:

1. Используй только проверенные сведения.
2. Указывай ссылки на реальные файлы проекта.
3. Не копируй большие фрагменты кода.
4. Избегай повторения информации из AGENTS.md.
5. Чётко отделяй существующие правила от рекомендаций.
6. Делай документацию удобной для использования AI-агентом.
7. Не включай секреты или чувствительные данные.

После создания каждого документа:
- проверь достоверность;
- проверь отсутствие противоречий с AGENTS.md;
- покажи краткое содержание;
- дождись моего подтверждения перед созданием следующего.

В конце проверь все относительные ссылки между документами.
